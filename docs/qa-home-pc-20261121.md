이벤트 발생을 재현하기 위해 기존 난수 시드를 고정했습니다. 은퇴 분기는 두 번째 경기 전 건강을 은퇴 기준보다 1 높게 설정해 검증했습니다. 무조정 장기 커리어 완주는 이번 범위에 포함하지 않았습니다.

390×845, 430×932, 560×1213에서 각각 22장씩 캡처했습니다. 하단 메뉴 경계, 전투 버튼의 고정 영역, 메뉴와 본문의 가독성을 확인했습니다. 모든 폭에서 휠 입력으로 스크롤이 0 → 97 → 0으로 이동했고 주요 전환은 실제 좌표로 눌렀습니다. 저장소의 디자인 문서와 레퍼런스 에셋을 사용했습니다. 별도의 원본 시안 파일과 실제 iPhone 터치·안전 영역은 확인하지 못했습니다.

## 검사 재현

Python 명령은 저장소 루트에서 실행합니다.

```powershell
python -X utf8 tools/test_data.py
python -X utf8 tools/test_gameplans.py
python -X utf8 tools/test_career_logic.py
python -X utf8 tools/project_sanity.py
python -X utf8 tools/validate_release_font_v10.py
```

Windows의 `core.autocrlf=true` 체크아웃에서 Noto Sans KR 라이선스 해시가 달라졌습니다. 이 파일만 LF로 고정했고 새 체크아웃에서 원본 Git 블롭 해시가 유지되는 것을 확인했습니다.

Windows에서는 테스트가 실제 저장을 지우지 않도록 별도 `APPDATA`를 사용합니다. `$godot`은 검증된 `Godot_v4.7.2-stable_win64_console.exe` 경로입니다.

```powershell
$env:APPDATA = Join-Path $env:TEMP ("twelve-count-_sandbox_user_data-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $env:APPDATA | Out-Null
& $godot --headless --editor --path . --quit
& $godot --headless --path . --script res://tests/v08_first_five_minutes_smoke.gd
& $godot --headless --path . --script res://tests/v24_scouting_weigh_in_smoke.gd
& $godot --headless --path . --script res://tests/fight_fixed_hud_smoke.gd
```

기존 계체 테스트는 씬을 해제하고 즉시 리소스를 다시 불러오는 과정에서 Windows의 `0xc0000005`로 중단됐습니다. 한 번 로드한 PackedScene에서 매번 새 인스턴스를 만들어 동일한 재진입·롤백 검증을 유지했고, 계체 통과·긴급 감량·실패 2개 구간의 단언문이 모두 통과했습니다. 일부 헤드리스 명령 종료 시 Ogg 오디오 리소스 경고가 남습니다. [Godot 오디오 종료 이슈](https://github.com/godotengine/godot/issues/76745)
